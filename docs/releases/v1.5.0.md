# Browser Relay 1.5.0

Browser Relay 1.5 adds complete page reading, persistent JavaScript workflows, and managed browser sessions to your existing, logged-in Chrome. Local and remote workflows use the same extension executor.

## Highlights

- **Read complete content with usable context.** `read`, `tab.read()` and MCP `browser_read` preserve document order, article labels, full links and actionable refs. Read a selected subtree, include its same-origin and cross-origin frames, and follow `nextCursor` for long pages. Unread pages do not advance the diff baseline.
- **Keep scripts and browser handles between calls.** MCP `browser_exec` and CLI `repl` retain top-level `await`, variables and tab handles. Ordered action groups run in the extension and return the resulting state. Runtime output has its own recoverable pagination; one-shot CLI `exec` drains it before exiting.
- **Combine semantic and visual operations.** Use scoped role/name locators, fresh refs or CSS; combine text and screenshots with `observe({mode:'both'})`. Click, hover and drag support screenshot coordinate mapping. Readiness waits check controls before dispatch without replaying input.
- **Coordinate ownership of shared tabs.** Managed sessions claim tabs, renew leases, and support release, handoff and stop. The extension popup shows owners and lets the user stop a session while keeping its pages open.
- **Stop pending work reliably.** Request cancellation, timeouts and disconnects propagate through the SDK, CLI, MCP and hub. Errors retain task identity and available partial results. Cancellation stops subsequent Relay actions; it cannot undo dispatched input or a page's own requests.
- **Diagnose the actual running extension.** Protocol negotiation and `doctor` report the live executor version and instance, and explain when an older extension needs reloading.

## Upgrade from 1.4.x

```bash
npm install -g @linsoai/browser-relay@1.5.0
browser-relay install
browser-relay restart
browser-relay path
```

Reload the existing unpacked Browser Relay extension in Chrome using the extension folder shown by `path`. Both the CLI/daemon and extension must be updated; restarting the daemon alone does not update the running Chrome extension.

Then verify the running pair:

```bash
browser-relay capabilities
browser-relay doctor
browser-relay tabs
```

Update the installed Browser Relay skill for the agents you use, for example:

```bash
browser-relay skill install --agent codex
```

### Compatibility and deployment notes

- Existing CSS/HTTP commands remain available. A tab claimed by a managed session must be released or handed off before switching clients, including legacy commands and the local CDP bridge. MCP tools and persistent runtimes can have different session IDs; coordinate with `browser.sessionId`.
- Background pages may defer rendering. Scrolling requires a foreground tab or explicit `allowFocus`; semantic background clicks report when they use DOM activation.
- Session leases, element refs and continuation caches belong to the running extension/runtime and can expire on navigation, eviction or restart. Re-observe or establish a new session when an error requires it.
- Local scripts run with the agent's OS permissions. Process isolation supplies timeout/reset behavior, not an OS security sandbox.
- Self-hosted Node/Cloudflare hubs should be upgraded with this version for hub-side cancellation. Publishing the npm package or GitHub Release does not deploy an existing hub or update a Chrome Web Store installation.

## Validation

The release was independently reviewed with Astra. The ten issues found during development were fixed and reverified, including iframe omissions, reordered content, long-output truncation, CSS subtree reading, cancellation races, CDP connection compatibility and prerelease publishing guards.

Local checks: 124 unit tests passed (8 environment-dependent skips), and 36 isolated-browser tests passed. Additional checks covered 180,000-character/emoji reading, recovery after large log output, and real Node hub timeouts where no subsequent click executed. Worker packaging and type generation passed locally.

These results are not a claim of performance parity with Codex native Browser Use. The final version has not completed the logged-in X comparison, and deployed Cloudflare client-disconnect behavior was not exercised in this validation.
