## 本次执行范围

先进行交互式流程探索，再做确定性回放。正式回放中的“单步观察”表示每个动作后读取状态，
不表示每步都有一次新的模型决策。AX 两种路径成对交替，各 5 次；原生 Playwright 后续单独跑 5 次。
开始每题都重载页面并重新取得 AX 索引。表单任务的业务等待由 AX 自带的状态稳定等待或
Playwright 的结果可见等待满足，没有插入额外固定 sleep。

原生视口 1466 × 925；Relay 已补充同视口的可见 Chromium 对照。原生 Chrome 版本读取被
URL 策略阻止，记为 unknown，没有绕过。两个浏览器配置与后端不完全相同。
探索轮的经过时间与回放轮的内层工具时间分开保存；计时闭包问题修正后才开始正式回放。
15 次所有状态以去重字符串字典保存，每条操作引用对应 stateId，保留逐操作毫秒计时。

[CUA 回放代码](codex-native-replay.js)保存了本次执行方法，整理为统一入口。先启动
`npm run bench:serve`，在 CUA 用 `cua.createBrowserTab('chrome', fixtureUrl, {sessionName:'🧪 原生同题对比'})`
得到 `nativeBench`，读取初始状态，再将回放代码放入持久 CUA REPL。它不是普通 Node 脚本，
也没有导入替代的浏览器驱动。每一对 AX 流程在一个外层工具调用中执行，原始观察在 `samples` 中保留。

## 连接与安装

1. 通过 CUA 的 Chrome 原生应用窗口访问官方扩展商店，安装 ChatGPT 扩展。
2. 按[官方说明](https://learn.chatgpt.com/docs/chrome-extension)，桌面应用“设置 → Computer use”中启用对应浏览器，直到显示 Manage。
3. 用 `cua.getState()` 确认浏览器可用，再用返回的浏览器 ID 新建专用测试标签。
4. 如果 CUA 拒绝操作 Codex 自身设置，由用户完成设置部分。不能通过脚本替代被禁止的操作。
5. 原生 `getApp('com.google.Chrome')` 与扩展支持的 Browser Tab 是两条不同通路。即使前者成功，也不能将其结果标为后者的性能。

## 同题与验证

启动 `npm run bench:serve`，使用其打印的本机 URL。服务不进行外部业务操作。

统一任务文本：

> 在当前测试页把 Search 填为 invoice，Owner 选为 Alice，勾选 Active only，点击 Search records。等待页面显示 Found: invoice / alice / active，然后停止。使用当前页面状态定位元素。

本次工具比较可使用已知任务，但不能包装成未知网页的模型盲测。若评测模型能力，应另开干净会话，不向模型提供源码、预先写好的定位器或成功轨迹。

## 两种原生流程

- 单步观察：初始 AX；每个会影响下一步选择的动作后读取 AX；看到成功状态后结束。
- 短批处理：初始 AX；在已知目标和状态允许时把动作放在一个 `js` 调用；遇到下拉菜单等新 UI 时先观察并重新取得索引；最后读取 AX 核验结果。

禁止跨 reload 复用 AX 索引。下拉框不能假定支持 `setValue`；应按实际暴露的能力操作。不加没有依据的固定 sleep，也不以 DOM 写入直接伪造业务结果。首轮发现的限制和恢复步骤必须保留，不能只统计成功重试。

## 计时口径

| 指标 | 定义 |
| --- | --- |
| 准备时间 | 创建浏览器、安装/连接、打开测试页、页面重置；单独记录 |
| 工具执行时间 | 每次 CUA `js` 内用 `Date.now()` 记录 API 调用开始、结束，累加；含该工具内部状态稳定等待 |
| 会话经过时间 | 初始观察开始到成功状态返回，包含模型决策及调用间调度；不能称为纯工具延迟 |
| Agent 工具调用数 | 外层 `js` 调用数量 |
| 浏览器 API 次数 | click、setValue、pressKey、getAXState 等实际数量；与外层调用数分列 |
| 观察量 | 每次 AX 状态 UTF-8 字节数之和；截图单独记录编码、尺寸及实际可获取的字节数 |
| 结果 | 精确成功文本、是否纠错、失败阶段、用户接管、超时；失败样本保留 |

至少交替运行两种流程各 5 次。浏览器版本、模式（headed/headless）、视口、设备缩放、模型和推理档位、网络条件必须记录；无法从环境确认的值写 unknown，不猜测。

Relay 已有结果来自 headless Chromium；实际 Chrome 原生通常是 headed，两者环境并不完全一致。公平的性能结论需要补跑相同可见浏览器条件下的 Relay 对照。原生接口没有暴露的 CDP 命令数量记 null，不能写 0，也不能拿 Relay 逻辑命令数与原生外层工具次数比较。

不能给整个 Codex 原生链路套用“Relay→扩展 50 ms”数字：这是 Relay 专属注入点。原生网络链路没有等效注入时，只报告原生默认环境数据。
